# 数值型环境变量缺少 NaN 防护

**日期**：2026-06-09
**分类**：Nuxt
**严重程度**：Critical

## 问题描述

`nuxt.config.ts` 中读取数值型环境变量时，直接使用 `Number()` 转换：

```ts
flushIntervalMs: process.env.NUXT_PUBLIC_TRACKER_FLUSH_INTERVAL_MS
  ? Number(process.env.NUXT_PUBLIC_TRACKER_FLUSH_INTERVAL_MS)
  : 3000,
```

若 `.env` 文件中写入无效值（如 `NUXT_PUBLIC_TRACKER_FLUSH_INTERVAL_MS=abc`），`Number('abc')` 返回 `NaN`，导致 Tracker 内部的 `setInterval` 定时逻辑静默失效，埋点数据不会被刷新和上报，且无任何错误提示。

受影响字段：`flushIntervalMs`、`batchSize`、`idleTimeoutMs`、`tracesSampleRate`。

## 根本原因

`Number()` 对无效字符串不抛错，而是返回 `NaN`。原代码只判断了"值是否存在"（truthy check），没有判断"转换结果是否合法"（`Number.isFinite`）。

## 解决方案

抽取 `envNumber` 辅助函数，统一处理转换与回退：

```ts
function envNumber(key: string, fallback: number): number {
  const raw = process.env[key]
  if (!raw) return fallback
  const n = Number(raw)
  return Number.isFinite(n) ? n : fallback
}

// 使用
flushIntervalMs: envNumber('NUXT_PUBLIC_TRACKER_FLUSH_INTERVAL_MS', 3000),
batchSize: envNumber('NUXT_PUBLIC_TRACKER_BATCH_SIZE', 10),
idleTimeoutMs: envNumber('NUXT_PUBLIC_TRACKER_IDLE_TIMEOUT_MS', 30 * 60 * 1000),
tracesSampleRate: envNumber('NUXT_PUBLIC_SENTRY_TRACES_SAMPLE_RATE', isProd ? 0.1 : 1.0),
```

`Number.isFinite` 同时排除 `NaN` 和 `Infinity`，比 `isNaN` 更严谨。
