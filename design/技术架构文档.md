## 4. 状态管理架构

### 4.1 Store 总览

项目使用 **Pinia 3** 进行状态管理，采用 Composition API 风格（`setup` 函数）。

#### Auth Store（`stores/auth.ts`）

```typescript
// 状态
token: string | null           // JWT Access Token
refreshToken: string | null    // JWT Refresh Token
user: AuthUser | null          // { id, username }

// 计算属性
isAuthenticated: boolean       // token 或 refreshToken 存在即为 true

// 方法
initAuthFromCookie()           // 从 Cookie 恢复认证状态
setAuth({ token, refreshToken, user })  // 设置认证（内存 + Cookie 双写）
clearAuth()                    // 清除认证（内存 + Cookie 双清除）
```

**Cookie 策略**：
- `auth_token`：存储 Access Token
- `refresh_token`：存储 Refresh Token
- 仅在客户端（`import.meta.client`）操作 Cookie

#### Theme Store（`stores/theme.ts`）

```typescript
// 状态
mode: 'system' | 'light' | 'dark'   // 主题模式

// 方法
setMode(value)                        // 设置主题模式
```

#### UI Store（`stores/ui.ts`）

```typescript
// 状态
authModalOpen: boolean              // 认证弹窗是否打开
authModalView: 'login' | 'register' // 当前视图

// 方法
openAuthModal(view)                 // 打开弹窗（指定登录/注册视图）
closeAuthModal()                    // 关闭弹窗
```

### 4.2 数据流

```
用户操作 → UI Store (弹窗控制)
         → Auth Store (登录/注销)
         → API 层 (useApi)
         → 后端服务
         → 响应数据 → Store 更新 → 视图响应式更新
```

## 5. API 层封装设计

### 5.1 核心客户端（`composables/useApi.ts`）

`useApi` 是全局唯一的 HTTP 客户端工厂，基于 Nuxt 内置的 `$fetch` 封装。

#### 核心特性

| 特性               | 实现方式                                           |
| ------------------ | -------------------------------------------------- |
| **BaseURL 双通道** | 服务端走内网直连（`apiSecretBase`），客户端走 Nginx 代理（`apiBase`） |
| **Bearer Token**   | `onRequest` 拦截器自动附加 Authorization 头        |
| **401 静默刷新**   | 自动使用 refresh_token 刷新，刷新期间挂起其他 401 请求 |
| **请求去重**       | 基于 `Method+URL+Params+Body` 指纹的 Promise Lock  |
| **错误 Toast**     | 客户端自动弹出 Nuxt UI Toast，2 秒防抖             |
| **凭证携带**       | `credentials: 'include'`                           |

#### 请求流程

```
发起请求 → 生成请求指纹
    ↓
[命中锁?] → 是 → 复用已有 Promise
    ↓ 否
附加 Bearer Token → 发送请求
    ↓
[响应 code === 200?] → 是 → 返回 data
    ↓ 否
[状态码 401?] → 否 → handleError (Toast 提示)
    ↓ 是
[已有刷新任务?] → 是 → 等待刷新结果
    ↓ 否
发起 refresh_token 请求
    ↓
[刷新成功?] → 是 → 重试原请求
    ↓ 否
清除认证 → 弹出登录弹窗
```

#### 对外接口

```typescript
const { get, post, put, del } = useApi()

get<T>(url, params?, options?)    // GET 请求
post<T>(url, body?, options?)     // POST 请求
put<T>(url, body?, options?)      // PUT 请求
del<T>(url, options?)             // DELETE 请求
```

### 5.2 模块化 API

每个业务模块独立封装，遵循统一模式：

```typescript
// composables/api/[module].ts
export function use[Module]Api() {
  const { get, post } = useApi()

  async function list(params) { return await get<T>('/path', params) }
  async function detail(id)   { return await get<T>(`/path/${id}`) }

  return { list, detail }
}
```

#### 已实现模块

| 模块     | 文件              | 方法                                                     |
| -------- | ----------------- | -------------------------------------------------------- |
| Home     | `api/home.ts`     | `getHomeConfig()`                                        |
| Auth     | `api/auth.ts`     | `getInfo()`                                              |
| User     | `api/user.ts`     | `getInfo()`, `updateInfo()`, `updatePassword()`, `getCaptcha()` |
| Product  | `api/product.ts`  | `getDetail(id)`, `search(params)`                        |
| Category | `api/category.ts` | `list()`, `products(categoryId, page, pageSize)`         |
| Article  | `api/article.ts`  | `list()`, `detail()`, `related()`, `categories()`, `tags()`, `hot()`, `latest()`, `search()` |
| Cart     | `api/cart.ts`     | `list()`, `add()`, `update()`, `remove()`, `clear()`     |
| Order    | `api/order.ts`    | `create()`, `list()`, `detail()`, `cancel()`, `pay()`, `confirm()` |

## 6. 路由与中间件设计

### 6.1 路由表（文件系统路由）

| 路径                | 文件                        | Meta 配置                               |
| ------------------- | --------------------------- | ---------------------------------------- |
| `/`                 | `pages/index.vue`           | 默认                                     |

| `/blog`             | `pages/blog/index.vue`      | 默认                                     |
| `/blog/:id`         | `pages/blog/[id].vue`       | 默认                                     |
| `/ai-page`          | `pages/ai-page.vue`         | `hideNavbar: true, hideFooter: true`     |
| `/character/:id`    | `pages/character/[id].vue`  | `hideFooter: true, forceCapsule: true`   |
| `/about`            | `pages/about.vue`           | `hideFooter: true`                       |

### 6.2 路由 Meta 类型

```typescript
interface PageMeta {
  hideNavbar?: boolean      // 隐藏导航栏
  hideFooter?: boolean      // 隐藏页脚
  hideFloatingMenu?: boolean// 隐藏悬浮菜单
  forceCapsule?: boolean    // 强制胶囊导航样式
}
```

### 6.3 中间件

#### Auth Middleware（`middleware/auth.ts`）

- **用途**：保护需登录才能访问的页面
- **逻辑**：检查 `authStore.isAuthenticated`，未认证时弹出登录弹窗并阻止导航
- **使用方式**：`definePageMeta({ middleware: 'auth' })`

#### Guest Middleware（`middleware/guest.ts`）

- **用途**：已登录用户不可访问的页面（如独立登录页）
- **逻辑**：已认证时重定向到首页
- **使用方式**：`definePageMeta({ middleware: 'guest' })`

### 8.2 事件模型

```typescript
type EventType = 'page_view' | 'error' | 'custom' | 'expose' | 'click'

interface EventPayload {
  app_id: string          // 应用标识
  device_id: string       // 设备唯一标识

  referrer?: string       // 来源页
```


### 11.2 Git Hooks

```json
{
  "simple-git-hooks": {
    "pre-commit": "npx lint-staged",
    "pre-push": "npm run lint"
  }
}
```

**lint-staged 规则**：
- `*.{js,ts,vue}` → `eslint --fix` + `prettier --write`
- `*.{json,css,scss,md}` → `prettier --write`

### 11.3 开发命令

| 命令              | 说明                     |
| ----------------- | ------------------------ |
| `pnpm dev`        | 启动开发服务器           |
| `pnpm build`      | 构建生产版本             |
| `pnpm preview`    | 预览构建产物             |
| `pnpm generate`   | 生成静态站点             |
| `pnpm lint`       | 代码检查                 |
| `pnpm lint:fix`   | 代码检查并自动修复       |
| `pnpm format`     | 格式化所有文件           |

### 11.4 构建配置

```json
{
  "scripts": {
    "build": "set NODE_OPTIONS=--max-old-space-size=4096 && nuxt build"
  }
}
```

构建时分配 4096MB 内存，确保大型项目构建不溢出。
