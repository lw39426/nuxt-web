> 版本：v1.0
> 最后更新：2026-09
> 适用范围：`app/pages/profile` 全模块 + 个人中心侧边栏 / 全局悬浮菜单
> 读者：团队前端同事、功能维护者

---

## 1. 这份文档解决什么问题

个人中心支持「马卡龙 / 薄荷」两套皮肤，可随时切换、刷新后保持。整套实现只有 **4 个新增文件 + 3 个改造点**，核心思想一句话概括：

> **颜色不写在页面里，页面只引用语义变量；皮肤只负责给变量赋值。**

因此：新增一套皮肤 = 新增一个 CSS 变量块 + 往清单数组里加一项，**不需要改任何页面**。

## 2. 架构总览

```
┌──────────────────────────────────────────────────────────────┐
│  用户点击色卡                                                 │
└───────────────┬──────────────────────────────────────────────┘
                │
                ▼
   ProfileSkinSwitcher.vue（完整 / 紧凑两种形态）
                │  setSkin('mint')
                ▼
   useProfileSkin.ts  ── 模块级单例 ref<ProfileSkin>            │
     · 更新状态                                                  │
     · localStorage.setItem('youmi-profile-skin')                │
     · document.documentElement.dataset.profileSkin = 'mint'     │
                │                                                │
                ▼                                                │
   <html data-profile-skin="mint">  ← 唯一的"开关"                │
                │                                                │
                ▼                                                │
   profile-skins.css                                             │
     [data-profile-skin='mint'] { --skin-accent: ... }           │
     .dark[data-profile-skin='mint'] { ... }  ← 亮暗自动翻转      │
                │                                                │
                ▼                                                ▼
   页面样式：class="text-skin" / background: var(--skin-hero-bg)
   （页面零皮肤感知，换肤 = 变量整体重算）
```

**关键点**：皮肤切换不经过 Vue 组件重渲染，只改 `<html>` 上的一个属性，由 CSS 变量继承完成整页联动，因此切换零成本、无闪烁。

## 4. 变量体系：`profile-skins.css`

### 4.1 文件结构

文件按「皮肤 × 亮暗」四个块组织，顺序即优先级思路：

```
:root, [data-profile-skin='macaron']       ← 默认皮肤（未设置属性时回落）
.dark [data-profile-skin='macaron'],
.dark[data-profile-skin='macaron']         ← 马卡龙暗色

[data-profile-skin='mint']                 ← 薄荷亮色
.dark [data-profile-skin='mint'],          ← 薄荷暗色
.dark[data-profile-skin='mint']

[data-profile-skin] { ...工具类... }        ← 工具类，作用域限定
.profile-skin-scope { ...Nuxt UI 映射... }  ← 个人中心 primary 色
```

> 暗色选择器写成 `.dark [data-skin]` **和** `.dark[data-skin]` 两支，是为了兼容 `<html class="dark" data-profile-skin="mint">` 属性与类在同一元素上的情况（Nuxt UI 的 colorMode 把 `.dark` 挂在 `<html>`）。

### 4.2 变量分组表（写页面时按这张表选变量）

### 4.3 两套皮肤的色彩策略差异（设计意图）

- **macaron（默认）**：全新独立色板，薰衣草紫 `#7c5cbf` 为主色，Hero 用 **三层 radial-gradient 叠加**做弥散光（紫左上 8%/0% → 桃粉中右 65%/25% → 奶黄右下 100%/100%）。
- **mint**：**大量复用全站 `--brand-*` token**（`--skin-solid: linear-gradient(135deg, var(--brand-400), var(--brand-600))`），因此薄荷皮肤与全站品牌绿天然联动；Hero 是单条 118° 线性渐变。

> 这条差异是刻意的：macaron 走"独立设计语言"，mint 走"与站点主色一致"。新增皮肤时先决定走哪条路线，能省掉一半调色工作。

### 4.4 亮暗适配机制

**页面里完全不写 `dark:` 分支**。亮色值写在默认块，暗色值写在 `.dark [data-profile-skin=...]` 块，同名变量覆盖即可。以 `--skin-ink` 为例：

| 皮肤 | 亮色 | 暗色 | 说明 |
| --- | --- | --- | --- |
| macaron | `#5b4a8a` 深紫 | `#c9b8ee` 浅紫 | 暗底需要浅色文字 |
| mint | `#0a5c44` 深绿 | `var(--brand-300)` = `#5ce6c0` | 亮绿，暗色下对比度充分 |

暗色下 `--skin-chip-bg` 等底色的常见处理是**从实色改成半透明 rgba**（如 macaron `#ece5f9` → `rgba(139,112,219,0.16)`），避免暗底上出现荧光色块。

### 4.5 工具类清单

作用域统一为 `[data-profile-skin]`（嵌套写法，等价 `[data-profile-skin] .text-skin`），避免泄漏到非个人中心页面：

| 工具类 | 等价效果 | 替代的原写法 |
| --- | --- | --- |
| `.text-skin` | `color: var(--skin-accent)` | `text-brand-500` |
| `.text-skin-strong` | `color: var(--skin-ink-strong)` | — |
| `.text-on-skin` | `color: var(--skin-ink-on)` | `text-white`（实底上） |
| `.bg-skin` | `background-color: var(--skin-accent)` | `bg-brand-500` |
| `.bg-skin-soft` | `background-color: var(--skin-chip-bg)` | `bg-brand-soft` |
| `.bg-skin-soft\/50` | `rgba(var(--skin-accent-rgb), 0.09)` | `bg-brand-soft/50` |
| `.bg-skin-solid` | 渐变底 + 投影 + 文字色（三合一） | 手写 style |
| `.bg-skin-fill` | `background-image: var(--skin-fill-gradient)` | — |
| `.bg-skin-card` | `background-image: var(--skin-card-gradient)` | — |
| `.bg-skin-tab` | `background-color: var(--skin-accent)` | tab 指示条 |
| `.ring-skin` | 设置 `--tw-ring-color` | `ring-brand-500` |
| `.border-skin` | `border-color: var(--skin-chip-border)` | `border-brand-500` |
| `.group:hover .group-hover\:text-skin` | group hover 变主色 | `group-hover:text-brand-500` |

> ⚠️ **注意**：工具类被限定在 `[data-profile-skin]` 下，而该属性由 `useProfileSkin` 在客户端 `onMounted` 时写入 `<html>`。所以这些类**只在个人中心内、且恢复执行后**生效。跨页面通用组件若要用皮肤色，请直接用 `var(--skin-*)`（变量本身始终有值，`:root` 已兜底 macaron），或确保该组件仅在个人中心渲染。

## 5. 状态管理：`useProfileSkin.ts`

### 5.1 模块级单例

状态定义在**模块作用域**而非函数内：

```ts
const skin = ref<ProfileSkin>('macaron')
const restored = ref(false)
```

所有调用方共享同一份 `skin`。这正是"悬浮菜单切换 → 侧边栏色卡同步高亮"的原因——两个组件读的是同一个 ref，无需 props 透传、无需 Pinia。

### 5.2 对外 API

```ts
const { skin, skins, setSkin, restore } = useProfileSkin()
```

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `skin` | `Readonly<Ref<ProfileSkin>>` | 当前皮肤（只读，强制走 `setSkin` 修改） |
| `skins` | `PROFILE_SKINS` | 皮肤清单，含 `id / name / desc / preview` |
| `setSkin` | `(v: ProfileSkin) => void` | 切换 + 持久化 + 同步 DOM |
| `restore` | `() => void` | 从 localStorage 恢复（幂等） |

### 5.3 三个必须理解的实现细节

**① `readonly(skin)`**
对外只读，防止页面直接赋值绕过持久化与 DOM 同步。要改只能调 `setSkin`。

**② `normalizeSkin()` 脏数据防御**
localStorage 里可能存着历史版本/手改的非法值，`normalizeSkin` 用 `PROFILE_SKINS.some(...)` 校验，非法值返回 `null` 并回落默认皮肤。`setSkin` 同样先校验再写入。

**③ SSR 安全性（最重要）**

Nuxt SSR 下页面会在服务端渲染成 HTML，若服务端渲染时读 localStorage 得到 mint、而客户端首屏默认 macaron，就会产生**水合不匹配（hydration mismatch）**。

这里的处理方式：

```ts
function restore() {
  if (!import.meta.client || restored.value) return   // 服务端直接跳过
  restored.value = true                               // 幂等标记
  // ...读 localStorage → 更新 skin → applyToDom
}
```

- `restore()` 只由个人中心入口在 `onMounted` 调用（见 [profile.vue](file:///e:/公司项目/nuxt-web/app/pages/profile.vue#L14-L15)），`onMounted` 保证发生在水合之后；
- 服务端渲染始终用默认 macaron，客户端首屏与其一致，水合完成后再切到用户皮肤；
- `restored` 标记保证多处挂载（悬浮菜单 + 侧边栏 + 布局壳）只真正执行一次。

> 这也是切换器组件自身在 `onMounted` 也调了一次 `restore()` 的原因：让切换器成为**自包含**组件，任何位置挂载都能独立工作，幂等性保证不会重复执行。

**④ `applyToDom()` 是唯一的 DOM 写入口**

```ts
document.documentElement.dataset.profileSkin = value
```

`dataset.profileSkin` 对应 `data-profile-skin` 属性。所有皮肤切换最终都收敛到这一行——**CSS 层唯一需要关心的开关**。

### 5.4 持久化

- key：`youmi-profile-skin`（常量 `STORAGE_KEY`）
- 读写均包 `try/catch`：隐私模式下 localStorage 可能抛异常，失败时静默降级（不持久化 / 用默认皮肤），不阻塞渲染。

## 6. 切换器组件：`ProfileSkinSwitcher.vue`

### 6.1 双形态

```
<ProfileSkinSwitcher />          → 完整模式：纵向色卡列表
                                   预览色块 + 名称 + 描述 + 选中对勾
                                   用于悬浮菜单面板（空间充裕）

<ProfileSkinSwitcher compact />  → 紧凑模式：横向渐变条并排
                                   选中描边 + 白色对勾
                                   用于侧边栏（空间紧张）
```

### 6.2 实现要点

- `withDefaults(defineProps<{ compact?: boolean }>(), { compact: false })`，只有 `compact` 一个 prop；
- 预览色不读 CSS 变量，直接取 `skins[i].preview` 内联 `background`。**原因**：预览色需要"同时展示所有皮肤"，而 `--skin-*` 变量只会是当前皮肤的值，故由 JS 常量承载；
- `preview` 值必须与 `profile-skins.css` 中对应皮肤的实底渐变保持视觉一致（新增皮肤时两处都要写）；
- 无障碍：按钮带 `aria-pressed` 与 `aria-label`（紧凑模式）/ `title`（完整模式）；
- 未使用 `<style>` 之外的任何 UI 库组件，样式全部 scoped，避免污染。

> 预览色与真实皮肤色存在两处维护点，是当前实现的**已知取舍**：换来的是切换器可脱离皮肤上下文独立展示全部选项。

## 7. 页面接入方式（新增/改造页面时看这一节）

### 7.1 三种写法，按场景选择

**① 能用工具类就用工具类（首选）**

```vue
<!-- 强调图标 -->
<span class="i-carbon-crown text-skin" />
<!-- 淡底图标盒 -->
<div class="bg-skin-soft text-skin"><span class="i-carbon-crown" /></div>
<!-- 进度条填充 -->
<div class="bg-skin-fill" :style="{ width: percent + '%' }" />
<!-- 头像实底 -->
<div class="bg-skin-solid">YM</div>
<!-- 表单聚焦环 -->
<input class="focus-visible:ring-2 focus-visible:ring-skin" />
```

**② 复杂组合/渐变/伪元素 → scoped 样式里直接写变量**

```css
.hero {
  background: var(--skin-hero-bg);
}
.hero-blob--a {
  background: var(--skin-blob-a);
}
.percent-pill {
  color: rgb(var(--skin-accent-rgb) / 0.55);
  background: var(--skin-glass);
  box-shadow: var(--skin-shadow-btn);
}
```

**③ 传给组件的 props（如 `ProfileRowItem`）**

```vue
<ProfileRowItem icon-bg="bg-skin-soft" icon-color="text-skin" subtitle-class="text-skin" />
```

### 7.2 排查清单：页面看起来"没换肤"时

按顺序检查：

1. 色值是不是写死了（`#7c5cbf`、`text-brand-500`、`bg-purple-500`）？
2. 工具类是否写在了 `[data-profile-skin]` 作用域之外的元素上（如 `Teleport` 到 body 的浮层、`position: fixed` 的独立根节点）？→ 改用 `var(--skin-*)`
3. 该"皮肤"语义是否其实应该由**全站主题变量**承担？皮肤系统只管个人中心，不要污染全局
4. 新页面是否在 `app/pages/profile/` 下（由 `profile.vue` 布局壳包裹）？只有在这里才会自动获得 `data-profile-skin` 与 `profile-skin-scope`

### 7.3 Nuxt UI 组件主色映射

Nuxt UI 的 `UButton(color="primary")`、`UInput` 聚焦态等读的是 `--ui-primary`，默认是品牌绿。个人中心通过布局壳根节点上的 `.profile-skin-scope` 局部覆盖：

```css
.profile-skin-scope {
  --ui-primary: var(--skin-accent);
  --ui-color-primary-500: var(--skin-accent);
}
```

```vue
<!-- profile.vue 根节点 -->
<div class="profile-skin-scope bg-surfaceMuted dark:bg-canvas min-h-screen">
```

这样个人中心内所有 Nuxt UI 组件的主色随皮肤变化，而**其他页面仍是品牌绿**（作用域不泄漏）。

## 8. 新增一套皮肤：完整步骤

假设新增 `sakura`（樱花粉）：

1. **`profile-skins.css`**：复制一份 `[data-profile-skin='mint']` 块 → 改名 `sakura` 并调色；再复制一份暗色块 `.dark [data-profile-skin='sakura'], .dark[data-profile-skin='sakura']` 调暗色值。
2. **`useProfileSkin.ts`**：
   - 类型加联合成员：`export type ProfileSkin = 'macaron' | 'mint' | 'sakura'`
   - `PROFILE_SKINS` 数组追加一项 `{ id, name, desc, preview }`，`preview` 取该皮肤 `--skin-solid` 的近似渐变。
3. **无需改任何页面**——切换器按 `skins` 数组自动渲染新色卡，所有页面通过变量自动跟随。
4. 验收：切换后逐页确认亮/暗两种模式下的文字对比度、实底上文字可读性、暗色下无高饱和荧光块。

**清单**：不新增文件、不动组件、不动页面，共改 2 个文件。

## 10. 设计约束与已知取舍

| 项 | 说明 |
| --- | --- |
| **作用域** | 皮肤系统仅服务个人中心。放大到全站会让 `--skin-*` 与 `--brand-*` 语义重叠，需先统一 token 策略 |
| **变量命名** | 新增变量必须 `--skin-` 前缀，且在**四套色板块（2 皮肤 × 亮暗）都要定义**，否则某模式下取值落空 |
| **预览色双维护** | `PROFILE_SKINS[].preview` 与 CSS 实底渐变需人工保持一致（见 6.2） |
| **SSR 首屏** | 首屏固定渲染默认 macaron，水合后切换为用户皮肤。这是避免水合不匹配的有意设计，非 bug |
| **localStorage** | 单一 key `youmi-profile-skin`，非登录态绑定。同设备不同账号会共享皮肤偏好 |
| **不依赖 Pinia** | 模块级单例已满足需求，未引入 store。若将来皮肤需跨端同步（服务端存偏好），再升级为 Pinia + 接口 |
