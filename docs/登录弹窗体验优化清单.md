# 登录弹窗体验优化清单

本文用于评估并优化当前登录弹窗方案，在不破坏现有登录功能的前提下，提升转化率、可用性与一致性。

## 一、目标

- 保留当前“就地登录”的效率优势。
- 降低登录打断感，让用户尽量不离开当前任务。
- 兼容受限页面拦截、导航栏登录、注册切换等现有链路。
- 让登录过程在桌面端与移动端都可稳定使用。

## 二、当前方案的产品判断

登录弹窗适合做“轻量认证入口”，尤其适合：

- 顶部导航随时唤起登录。
- 当前页面任务未完成，但用户临时需要登录。
- 受限内容需要拦截后快速回到原页面。

但弹窗不适合承载所有认证场景，尤其是：

- 注册流程较长。
- 找回密码、短信验证、第三方登录等复杂流程。
- 移动端软键盘场景。

结论：弹窗应作为主入口，但建议保留完整登录页作为兜底方案。

## 三、优化清单

### P0 必做项

1. 登录后回到原目标页
   - 受限页面被拦截时，记录原始访问地址。
   - 登录成功后自动返回原页面，而不是只关闭弹窗。
   - 目的：减少登录后再找回内容的成本。

2. 保留当前登录入口链路
   - 导航栏登录按钮继续可用。
   - 受限路由拦截继续可自动唤起登录。
   - 根组件继续统一挂载弹窗，避免分散管理。

3. 错误提示改为弹窗内反馈
   - 不再优先使用浏览器原生 alert。
   - 在弹窗内部显示登录失败原因。
   - 验证码错误、密码错误、账号不存在等提示尽量区分。

4. 关闭后保留用户输入
   - 关闭弹窗时保留用户名、登录方式选择、记住账号状态。
   - 清空密码与验证码，避免安全风险。
   - 目的：减少重复输入成本。

### P1 建议项

5. 移动端改成更适合输入的展示形态
   - 小屏幕优先使用全屏登录页或底部抽屉。
   - 避免在窄屏里挤压输入框和验证码区域。
   - 目的：降低软键盘遮挡与误触。

6. 让验证码按需出现
   - 默认情况下不要过早增加用户负担。
   - 可以按后端配置、失败次数或风险策略再展示。
   - 目的：减少首轮登录摩擦。

7. 焦点与键盘行为完善
   - 打开弹窗后自动聚焦第一个输入项。
   - 支持 Esc 关闭。
   - 关闭后焦点回到触发按钮。
   - 目的：提升专业感和键盘可用性。

8. 登录与注册分层
   - 登录保持短链路。
   - 注册若信息较多，建议跳到完整注册页或单独步骤页。
   - 目的：避免弹窗内容过载。

### P2 可选项

9. 记住账号默认保留最近一次输入
   - 用户再次打开登录框时，自动带出上次用户名。
   - 密码不自动保存。

10. 登录方式做成清晰切换
    - 如果后续支持手机号、扫码、微信等方式，做成显式 tab 或分段按钮。
    - 避免把多个入口塞进一个视觉层级里。

11. 增加轻量状态反馈
    - 登录按钮显示 loading。
    - 验证码刷新时显示局部 loading。
    - 切换登录/注册时保持过渡一致。

## 四、功能不回退约束

优化时必须保留以下能力：

- 导航栏可唤起登录弹窗。
- 受限页面访问时可自动唤起登录弹窗。
- 登录成功后可正常写入认证状态。
- 注册成功后可切回登录视图。
- 验证码刷新可用。
- 关闭弹窗不影响页面正常浏览。

## 五、验收标准

- 访问需要登录的页面时，未登录用户能看到登录弹窗。
- 从导航栏打开登录弹窗时，不会跳页。
- 登录成功后，用户回到原始目标页或当前上下文。
- 关闭弹窗后，页面仍可继续正常操作。
- 桌面端和移动端输入体验都能正常使用。
- 不登录时，不会出现空白页或无法恢复的中断状态。

## 六、建议实施顺序

1. 先补登录成功后的回跳逻辑。
2. 再把错误提示从 alert 改为弹窗内展示。
3. 然后优化移动端展示形态。
4. 最后再考虑注册页拆分与登录方式扩展。

## 七、对应实现位置

- 全局挂载与路由接收逻辑：`app/app.vue`
- 路由拦截：`app/middleware/auth.ts`
- 登录弹窗主体：`app/components/AuthModal.vue`
- 导航栏触发入口：`app/components/AppNavbarLayout.vue`
