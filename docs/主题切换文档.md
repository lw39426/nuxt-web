# 主题切换（system / light / dark）功能文档

本项目使用 **`@nuxtjs/color-mode`**（由 `@nuxt/ui` 自动安装）负责主题开关，配合 **CSS 变量 + UnoCSS 语义类** 完成双主题渲染。本文档说明机制、涉及文件、以及未来调整时该改哪里。

---

## 一、目标与核心决策

- 三态主题：`system`（跟随系统）、`light`、`dark`，持久化保存在 `localStorage`。
- 切换立即生效：color-mode 给 `<html>` 添加/移除 `dark` class。
- `dark:` 双写已消灭：颜色统一收在 CSS 变量中（`theme.css`），`.dark` 出现时 `var()` 自动翻转，组件只需写 `bg-surface`、`text-fg` 这样的**语义类**。

## 二、机制概览（4 层）

```
① 引擎层   @nuxtjs/color-mode（nuxt.config.ts 的 colorMode 块）
           → 控制 <html> 上的 .dark class
② 事实源   app/assets/css/theme.css
           → CSS 变量：原始色板 + 语义 token（:root/.light 与 .dark 两块）
③ 映射层   uno.config.ts theme.colors
           → 把 var() 映射成语义类名（bg-canvas / text-fg / border-line …）
④ 组件层   组件直接写语义类，不再出现 bg-white dark:bg-* 双写
```

### 各单位职责

| 文件 | 职责 | 什么时候改 |
|------|------|-----------|
| `app/assets/css/theme.css` | 主题唯一事实源：token 定义 + 主题块 + `@apply` 组件类 | 换主题 / 调色 |
| `uno.config.ts` | 语义色板→类名映射；纯布局 shortcuts | 加映射 / 加布局类 |
| `nuxt.config.ts` `colorMode` | 开关引擎配置 | 改默认主题 / 存储 key |
| `app/components/AppFloatingMenu.vue` | 主题切换 UI（右侧悬浮面板） | 换图标 / 调交互 |

> 语义 token 速查表（该写什么类）：见 **[docs/tokens.md](./tokens.md)**。

> 旧机制文件已删除（`app/composables/useThemeMode.ts`、`app/plugins/theme.client.ts`），不要再引用。

## 三、nuxt.config.ts 的 colorMode 配置

```ts
colorMode: {
  preference: 'system',  // 默认主题
  fallback: 'light',     // 无偏好时的兜底
  storageKey: 'nuxt-color-mode',
  classSuffix: '',       // 只加 .dark，不加 .dark-*
  disableTransition: true
}
```

- color-mode 会把用户选择写入 `localStorage['nuxt-color-mode']`。
- `system` 模式下内部使用 `matchMedia('(prefers-color-scheme: dark)')` 自动跟随系统，并在系统变化时同步。
- 页面初始化时 color-mode 会在 `<head>` 注入内联脚本，避免首帧闪白/闪黑。

## 四、主题变量（theme.css）

- `:root, .light` 块 = 浅色语义 token；`.dark` 块 = 深色 token。
- 语义 token 清单：`--canvas` / `--canvas-elevated` / `--surface` / `--surface-muted` / `--glass-bg`、`--fg` / `--fg-muted` / `--fg-subtle`、`--line` / `--line-strong`、`--brand` 系列、`--accent` 系列、`--shadow-soft` / `--overlay`。
- 通过 `uno.config.ts` 的 `theme.colors` 映射为类名：`bg-canvas`、`text-fg-muted`、`border-line`、`hover:bg-brand-hover` 等，`.dark` 出现时自动翻转。

### 💡 两条铁的纪律（踩坑实录）

1. **禁止对 var() 色用 `/opacity`**：`hover:bg-brand/90` 的 `/90` 会被 UnoCSS 静默丢弃（生成不透明色却毫无警告）。需要透明度/交互态一律用 `-soft` / `-hover` / `-active` 变体。
2. **带颜色/状态的组合类放 theme.css 用 `@apply` 定义**，不要写 uno shortcuts —— shortcut 对多段色名（`text-fg-muted`）和变体存在静默丢弃 bug（unocss 66.5.10-beta）。

## 五、组件写法规范

```html
<!-- 推荐：单写语义类，双主题自动适配 -->
<div class="bg-canvas text-fg border-line">…</div>
<button class="bg-brand text-on-brand hover:bg-brand-hover active:bg-brand-active">主按钮</button>
<p class="text-fg-muted">次级文字</p>

<!-- 禁止 -->
<div class="bg-white dark:bg-black text-gray-900 dark:text-white">…</div>
<button class="bg-brand/90">…</button>
```

## 六、切换 UI（AppFloatingMenu.vue）

- 组件通过 `useColorMode()`（Nuxt 自动导入）读写主题：

```ts
const colorMode = useColorMode();
const mode = computed(() => colorMode.preference as 'system' | 'light' | 'dark');
const setMode = (value: 'system' | 'light' | 'dark') => { colorMode.preference = value; };
```

- 三个按钮：`system`（`i-carbon-screen`）/ `light`（`i-carbon-sun`）/ `dark`（`i-carbon-moon`）。
- 选中项用一个绝对定位的“滑动指示块”（`.theme-indicator`）高亮，位移由 CSS 变量 `--theme-index` 控制（0/1/2），用 `translate3d` + `transition-transform` 实现合成层动画。
- 无障碍：分组容器已加 `role="group"` + `aria-label`，每个按钮带 `:aria-pressed`。
- `app/pages/about.vue` 也直接使用 `useColorMode()` 做自定义切换，机制相同。

## 七、扩展新主题（oled / sepia 等）

在 `theme.css` 末尾新增一个块，覆盖需要的语义 token 即可（示例已注释在文件 §5）：

```css
[data-theme='oled'] {
  --canvas: #000;
  --surface: #050505;
  --fg: #eee;
}
```

> 注意：`data-theme` 仅用于“非明暗色调变体”扩展，**不要**用它替代 `.dark` 管理明暗，否则会破坏 color-mode 与 @nuxt/ui 的自动适配。

## 八、本地验证

1. `pnpm dev` 启动，确认控制台无 uno/unocss `unmatched utility` 告警。
2. 点右侧边缘悬浮把手 → 面板中切换 `system / light / dark`，全站背景/文字/卡片应正确变化。
3. 刷新页面，主题保持选择不变。
4. `system` 模式下切换系统深浅色，页面自动跟随。
5. 产物 CSS 中应存在语义类（如 `.text-fg-muted`），且全站无 `bg-brand/90` 一类被静默丢弃的样式。

## 九、常见问题排查

| 现象 | 排查 |
|------|------|
| `dark:` 不生效 | DevTools 检查 `<html>` 是否有 `dark` class；确认 `@nuxt/ui` 模块已安装 |
| 刷新后不生效 | 检查 `localStorage['nuxt-color-mode']` |
| `system` 不跟随系统 | 确认 preference 为 `system`，系统切换后刷新观察 |
| 某个区域该变色不变色 | 检查该处是否仍写了 `bg-white dark:bg-*` 双写（应迁移为语义类） |
| 颜色没按预期翻转 | 确认 token 值是否同时存在于 `:root/.light` 与 `.dark` 两块 |
