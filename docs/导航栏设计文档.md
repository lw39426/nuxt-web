# 导航栏设计文档 (AppNavbarLayout)

## 1. 设计概述

`AppNavbarLayout.vue` 是一个具备高性能滚动动画、响应式布局以及深色模式支持的现代化全局导航栏组件。该组件的核心设计理念是提供无缝的沉浸式体验，能够根据用户滚动行为在“全宽透明态”与“悬浮胶囊态”之间丝滑切换。

## 2. 核心特性

*   **双形态丝滑过渡**：
    *   **全宽透明态**：页面处于顶部时，导航栏融入背景，提供沉浸式的视觉体验。
    *   **悬浮胶囊态**：用户向下滚动页面时，导航栏收缩成带有毛玻璃效果的胶囊形状，节省屏幕空间并聚焦视线。
*   **路由级形态控制**：支持通过 Vue Router 的 `meta.forceCapsule` 属性，在特定页面（如角色详情页）强制锁定为悬浮胶囊形态。
*   **响应式设计 (RWD)**：
    *   **桌面端**：展示完整的横向菜单栏和操作按钮。
    *   **移动端**：自动折叠为汉堡菜单（Hamburger Menu），点击展开下拉抽屉。
*   **极致的性能优化**：采用 IntersectionObserver 结合 FLIP 动画技术，确保在不同设备上都能保持 60FPS 的流畅动画体验。

## 3. 核心技术原理

### 3.1 高性能滚动监听 (IntersectionObserver)

传统的导航栏吸顶通常使用 `window.addEventListener('scroll')`，这会引发频繁的重排，消耗大量性能。本组件采用了一种“哨兵模式”：

在模板的最顶部放置一个高度为 1px 的透明“哨兵元素”（Sentinel）：

```html
<div ref="sentinelRef" class="absolute top-0 left-0 h-1 w-full pointer-events-none bg-transparent z-0"></div>
```

利用 `IntersectionObserver` 异步监听这个哨兵元素是否离开视口：
*   **哨兵在视口内**：表示页面在顶部，导航栏呈现全宽透明态。
*   **哨兵离开视口**：表示用户向下滚动，导航栏切换为悬浮胶囊态。

这种方式将监听任务交给浏览器底层处理，完全不阻塞 JavaScript 主线程。

### 3.2 动画引擎：FLIP 架构

直接使用 CSS `transition` 修改 `width` 和 `padding` 会触发 Layout（重排），导致动画卡顿。该组件手动实现了 FLIP (First, Last, Invert, Play) 动画原则，将所有动画转换为 GPU 加速的 `transform` 操作：

1.  **First (记录初始)**：获取变形前导航栏外壳的 `BoundingClientRect`。
2.  **Last (计算终态)**：改变状态变量 `isScrolled` 触发 Vue 响应式更新类名，利用 `await nextTick()` 等待 DOM 更新后，获取终态的 `BoundingClientRect`。
3.  **Invert (反转位移)**：计算前后状态的宽、高比例 (Scale) 和位置差 (Translate)，使用 CSS `transform` 将元素瞬间拉回初始状态的视觉位置。
4.  **Play (播放动画)**：使用浏览器原生的 Web Animations API (`element.animate`)，将 `transform` 平滑过渡到 `scale(1, 1) translate(0, 0)`。

**关键细节：反向缩放 (Inverse Scale)**
当外层容器（Shell）缩小时，为了防止内部的内容（Content，如文字、图标）被挤压变形，组件对内容层施加了反向放大的 `transform` (`scale(1/sx, 1/sy)`)。外层的缩小与内层的放大相互抵消，保证了视觉上的完美无瑕。

### 3.3 无障碍与边界处理

*   **尊重无障碍设置**：监听 `(prefers-reduced-motion: reduce)`，如果用户在系统中开启了减弱动态效果，组件将跳过 FLIP 动画，直接进行状态切换。
*   **动画防抖与状态队列**：通过 `isAnimating` 锁和 `pendingScrolled` 队列，防止用户快速来回滚动导致动画冲突或状态错乱。

## 4. 视图层结构

组件模板结构划分为以下几个主要层次：

1.  **哨兵层 (Sentinel)**：用于触发 IntersectionObserver 状态变更。
2.  **定位容器层**：根据 `route.meta.forceCapsule` 动态应用 `fixed`（固定定位，脱离文档流）或 `sticky`（粘性定位）。
3.  **视觉外壳 (Nav Shell)**：执行 FLIP 动画形变的主体，控制背景色、圆角和阴影的切换。
4.  **内容层 (Nav Content)**：执行反向缩放的主体，内部使用 Flexbox 布局划分为：左侧 Logo、中间菜单（仅桌面端）、右侧操作区及移动端菜单开关。
5.  **移动端抽屉 (Mobile Menu)**：独立的下拉面板组件，通过 `v-show` 控制显示与隐藏。

## 5. CSS 性能优化策略

在 `<style scoped>` 块中，实施了以下关键优化：

```css
/* 将绘制影响尽量限制在导航内部，降低滚动时重绘范围 */
.nav-shell {
  contain: paint;
}

/* 确保合成层优化 */
[style*='will-change'] {
  will-change: transform;
}

nav {
  /* GPU 硬件加速 */
  transform: translateZ(0);
}
```

*   **`contain: paint`**：CSS Containment 属性，指示浏览器该元素的子元素不会溢出边界，使得浏览器可以将其作为一个独立的图层进行绘制，显著缩小重绘 (Repaint) 面积。
*   **`will-change: transform`** 和 **`transform: translateZ(0)`**：强制浏览器为导航栏分配独立的合成层 (Compositor Layer)，确保动画计算完全卸载到 GPU，释放 CPU 资源。

## 6. 配置与扩展

### 6.1 路由配置 (Route Meta)

在页面组件的 `definePageMeta` 中可以控制导航栏行为：

```typescript
definePageMeta({
  hideNavbar: false,      // 是否隐藏导航栏
  forceCapsule: true,     // 是否强制锁定为悬浮胶囊形态 (忽略滚动状态)
})
```

### 6.2 菜单项配置

通过修改组件内部的 `menuItems` 数组可以轻松增删菜单项：

```javascript
const menuItems = [
  { name: 'Products', href: '/products', icon: 'i-carbon-cube' },
  // ...
]
```

## 7. 总结

`AppNavbarLayout` 是一套结合了前沿性能优化手段的 UI 解决方案，不仅满足了复杂的高级交互设计需求，还保证了在各种设备上的极佳性能表现，是构建高质量 C 端展示页面的理想选择。
