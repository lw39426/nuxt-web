# 产品需求设计文档（反推版）

## 1. 文档说明

- 文档类型：反向分析产出（基于现有代码与接口实现）
- 适用范围：domeWeb Web 端（Nuxt 全栈）
- 版本：v1.0
- 日期：2026-04-01

## 2. 反推结论摘要

基于当前项目实现，产品呈现为一个“多场景 AI 驱动体验平台”，包含以下核心业务域：

1. AI 心理陪伴对话
2. 商品浏览与详情展示（电商演示）
3. 文章内容浏览（内容资讯演示）
4. 角色世界浏览（高动效沉浸式展示）
5. 登录注册壳页与全局主题/导航体验

当前形态更接近“产品化 Demo + 可扩展业务骨架”，而非完整商业闭环。前端已预留大量标准业务 API（用户、订单、购物车、文章扩展能力），但服务端仅实现了部分 Mock/基础接口。

## 3. 产品愿景与定位

### 3.1 产品愿景

构建一个融合 AI 陪伴、内容消费与商品触达的统一体验入口，形成“情绪互动 -> 内容理解 -> 商业转化”的连续用户路径。

### 3.2 产品定位

- 定位：AI 互动型内容与商品融合平台（Web）
- 阶段：验证期（体验与架构验证优先）
- 形态：前端高保真体验 + 后端可演进接口层

### 3.3 目标用户

1. 普通访客：浏览主页、内容与商品
2. 情绪陪伴用户：进入 AI 对话页进行倾诉和咨询
3. 潜在消费者：浏览商品分类与详情
4. 内容用户：浏览文章列表和详情
5. 运营/产品团队：验证交互方案、动效与性能策略

## 4. 产品范围（Scope）

## 4.1 本期已呈现范围（代码可验证）

1. 首页品牌化内容展示与 AI 问题入口
2. AI 多会话聊天（本地持久化、流式回复、错误重试）

6. 登录/注册 UI 页面

## 4.2 本期不纳入完整交付（已预留但未闭环）

1. 完整登录鉴权链路（接口落地、权限策略、刷新令牌）
2. 购物车与订单完整流程
3. 文章分类/标签/热门/搜索后端实现
4. 用户资料维护、密码修改、验证码服务

## 6. 核心用户流程

### 6.1 AI 陪伴主流程

1. 用户从首页输入问题并跳转 AI 页（query 注入初始问题）
2. 系统创建/切换会话并发送消息
3. 服务端进行输入校验并流式返回 AI 响应
4. 前端渲染消息、支持复制、错误重试
5. 会话按最近更新时间持久化（本地最多 3 条）

### 6.2 商品浏览流程

1. 用户进入商品列表按系列浏览
2. 点击商品进入详情页
3. 选择颜色、版本、数量、增值服务
4. 可执行加入购物车/立即购买 UI 操作（当前为交互壳）

### 6.3 内容浏览流程

1. 用户进入博客列表
2. 可进行分类标签选择（前端筛选演示）
3. 滚动触发“加载更多”
4. 进入文章详情并查看相关推荐

### 6.4 角色沉浸流程

1. 用户进入角色地区页
2. 切换地区后加载地区角色详情
3. 角色切换触发动效和背景切换
4. 空闲时预加载下一区域资源

## 8. 业务规则与约束

1. AI 功能受环境变量 AI_ENABLED 控制，可被全局关闭
2. AI 消息单条长度上限 4000 字符
3. AI 会话本地仅保留最近 3 个会话
4. 前端 API 统一要求响应结构 code/message/data
5. 页面可通过路由元信息控制导航栏、页脚和浮动菜单显隐

## 9. 数据对象（领域模型）

### 9.1 会话模型

- Session：id/title/updatedAt/messages[]
- Message：id/role/text

### 9.2 商品模型

- Product：基础信息 + 价格 + 评分 + 图片 + 规格选项 + 服务保障

### 9.3 文章模型

- ArticleBrief：id/title/summary/category/tags
- ArticleDetail：ArticleBrief + content

### 9.4 用户模型

- AuthUser：id/username
- AuthState：token/user

## 10. 非功能需求

### 10.1 性能

1. 首屏可交互时间在可接受范围内（面向演示场景）
2. 导航动效与角色页交互目标保持流畅
3. 重点页面图片使用懒加载
4. 长页面使用 content-visibility 优化渲染开销

### 10.2 可用性

1. 页面加载有可见反馈（全局加载器）
2. AI 异常具备可理解提示
3. 核心入口在移动端可达

### 10.3 安全与合规

1. Token 走 Bearer 头注入
2. 不在前端硬编码敏感密钥
3. AI 心理陪伴需保留风险场景提示（建议寻求专业帮助）

## 11. 指标设计（建议）

## 11.1 北极星指标

AI 有效会话完成率（发起会话并收到至少 1 条有效回复的比例）

## 11.2 业务指标

1. AI 模块：
   - 日活会话数
   - 平均会话轮次
   - 错误重试率
2. 商品模块：
   - 列表到详情点击率
   - 详情停留时长
3. 内容模块：
   - 文章阅读完成率
   - 无限滚动触发率

## 12. 里程碑规划（建议）

## M1：基础闭环（2-3 周）

1. 完成用户登录、退出、用户信息接口
2. 完成购物车 API 与前端联动
3. 完成文章分类/标签/热门/搜索接口

## M2：业务增强（2-4 周）

1. 订单流转闭环
2. AI 会话云端同步
3. 商品与内容真实数据接入

## M3：增长与运营（持续）

1. 事件埋点与漏斗分析
2. A/B 测试能力
3. 运营配置化（首页配置、推荐位、标签体系）

## 13. 风险与应对

1. 风险：前端接口定义领先于后端实现，联调成本上升
   - 应对：建立 API 状态矩阵（已实现/开发中/预留）并周更
2. 风险：AI 服务受外部模型可用性影响
   - 应对：模型降级、错误码标准化、可观测日志
3. 风险：多主题 + 高动效可能带来中低端设备卡顿
   - 应对：移动端降级策略与性能预算控制

## 14. 验收总则

1. 关键页面路由可访问且无阻断错误
2. AI 对话流程可完整走通（开启 AI_ENABLED 条件下）
3. 商品、文章、角色三大模块至少具备“可浏览、可切换、可返回”稳定体验
4. 预留能力在文档中明确，不与已上线能力混淆
