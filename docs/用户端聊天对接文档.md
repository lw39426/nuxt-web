# 用户端聊天对接文档

适用于使用 `socket.io-client` 的用户端 Web/H5。首版流程覆盖发起私聊、会话列表、历史分页、标记已读和实时文本消息。

## 1. 连接和认证

本地后端地址为 `http://localhost:5050`。REST 路径以 `/chat-system/chat` 开头，请求头携带 `Authorization: Bearer <access_token>`。Socket.IO 使用同一后端地址、默认命名空间 `/` 和 `path: '/socket.io'`，握手传 `auth: { token: accessToken }`。两处都使用用户登录返回的 access token，普通用户 JWT 的身份为 `user:<id>`。

如果前端走同源代理，将 `/chat-system/chat` 和 `/socket.io` 转发到后端，并为 `/socket.io` 启用 WebSocket Upgrade。跨域部署时将示例中的 `origin` 设为后端公开地址，HTTPS 页面使用 HTTPS 地址。浏览器客户端安装 `npm install socket.io-client@4`。

REST 成功返回 HTTP 200 和 `{ "code": 200, "message": "…", "data": {} }`。错误响应通常只有 `code` 和 `message`。HTTP 401 交给现有登录或 token 刷新流程，403 提示房间访问受限，400 展示后端业务提示。时间字段使用 ISO 8601 UTC（例如 `2026-11-14T02:30:00Z`），前端负责本地化显示。

## 2. 发起或打开私聊

从用户详情等入口取得对方用户 ID 后调用 `POST /chat-system/chat/rooms`。私聊的 `participants` 只放一名对方用户，当前登录用户由后端加入。与普通用户私聊使用 `NormalUser`，与已知管理员私聊使用 `AdminUser`。

```json
{
  "type": "private",
  "participants": [{ "user_id": 42, "user_type": "NormalUser" }]
}
```

新建成功示例：

```json
{
  "code": 200,
  "message": "聊天室创建成功",
  "data": {
    "room_id": 18,
    "type": "private",
    "name": "",
    "created_at": "2026-11-14T02:30:00Z",
    "participant_count": 2
  }
}
```

已有两人私聊时，同样返回 HTTP 200 和原 `data.room_id`。此时 `data.was_hidden` 表示本次是否自动恢复了当前用户隐藏的会话。两种成功响应都可以直接使用 `data.room_id` 打开聊天页，并刷新会话列表。

## 3. 加载会话列表

`GET /chat-system/chat/rooms?page=1&per_page=20&include_hidden=false`

`page` 默认 1，`per_page` 默认及上限均为 20，`include_hidden` 默认 `false`。响应在 `data.rooms`，按房间更新时间倒序。用 `room.id` 打开房间。私聊的 `name` 可以为空，标题和头像可从 `participants` 中按当前用户的 `(type, id)` 找到对方后读取。

```json
{
  "code": 200,
  "message": "获取聊天室列表成功",
  "data": {
    "rooms": [{
      "id": 18,
      "type": "private",
      "name": "",
      "created_at": "2026-11-14T02:30:00Z",
      "updated_at": "2026-11-14T02:31:00Z",
      "participants": [
        { "id": 7, "type": "NormalUser", "name": "小林", "avatar": null, "phone": null, "is_online": true, "last_seen_at": null, "online_status": "在线" },
        { "id": 42, "type": "NormalUser", "name": "小陈", "avatar": null, "phone": null, "is_online": true, "last_seen_at": null, "online_status": "在线" }
      ],
      "participant_count": 2,
      "unread_count": 1,
      "last_message": {
        "id": 120,
        "content": "你好",
        "message_type": "text",
        "created_at": "2026-11-14T02:31:00Z",
        "sender": { "id": 42, "type": "NormalUser", "name": "小陈", "avatar": null, "phone": null, "is_online": true, "last_seen_at": null, "online_status": "在线" }
      }
    }],
    "pagination": { "page": 1, "per_page": 20, "total": 1, "pages": 1, "has_next": false, "has_prev": false }
  }
}
```

未读徽标用 `unread_count`，它排除自己发送的消息，并基于当前参与者的 `last_read_at` 或 `joined_at` 计算。空会话的 `last_message` 为 `null`，有消息时 `sender` 也可能为 `null`。分页依据 `pagination.has_next`。收到 `new_message` 时可更新已知会话的预览，遇到新会话或需要同步未读数时刷新列表。

## 4. 加载历史并标记已读

进入聊天页时调用 `GET /chat-system/chat/rooms/18/messages?page=1&per_page=20`。`page` 默认 1，`per_page` 默认 20、最大 100。后端按 `created_at` 倒序，同一时间按 `id` 倒序。前端气泡按从旧到新展示，上滑时用 `pagination.has_next` 继续请求下一页。

```json
{
  "code": 200,
  "message": "获取消息历史成功",
  "data": {
    "messages": [{
      "id": 120,
      "content": "你好",
      "message_type": "text",
      "created_at": "2026-11-14T02:31:00Z",
      "sender": { "id": 42, "type": "NormalUser", "name": "小陈", "avatar": null, "phone": null, "is_online": true, "last_seen_at": null, "online_status": "在线" },
      "is_own": false
    }],
    "pagination": { "page": 1, "per_page": 20, "total": 1, "pages": 1, "has_next": false, "has_prev": false }
  }
}
```

历史消息所属房间取请求路径里的 `room_id`，响应逐条提供 `id` 和 `is_own`，`sender` 可为 `null`。页面可见且已显示最新消息时，调用 `POST /chat-system/chat/rooms/18/read`，无需请求体。当前会话可见时收到对方新消息，也可在显示后调用；后台收到消息时保留未读状态。

```json
{
  "code": 200,
  "message": "标记为已读",
  "data": { "room_id": 18, "last_read_at": "2026-11-14T02:31:00Z" }
}
```

服务端将当前参与者的已读时间推进到请求处理时房间的最后一条消息，无消息时使用当前时间。成功后可刷新会话列表同步未读徽标。接口提供会话级已读状态，前端无逐条已读参数，也没有发给对方的已读回执事件。

## 5. Socket.IO 收发

登录后建立连接并注册全局监听。后端认证成功会发 `connected`，随后可收个人房间里的 `new_message`。打开会话时可发送 `join_room`，以接收该房间的输入状态等事件；切换会话时发送 `leave_room` 离开 Socket.IO 房间。已连接的活跃参与者通过个人房间接收 `new_message`，因此会话列表页也能收到消息。

| 方向 | 事件 | 负载或行为 |
| --- | --- | --- |
| 服务端 → 客户端 | `connected` | `{status, message, user_id, user_type}` |
| 客户端 → 服务端 | `join_room` / `leave_room` | `{room_id}`，成功回 `room_joined` / `room_left` |
| 客户端 → 服务端 | `send_message` | `{room_id, content, type: 'text', temp_id}` |
| 服务端 → 客户端 | `message_ack` | 成功 `{temp_id, success: true, message_id, sequence, timestamp}`，失败 `{temp_id, success: false, error}` |
| 服务端 → 客户端 | `new_message` | `{message_id, room_id, content, message_type, sequence, created_at, sender, is_own}`，发送者也会收到 |
| 客户端 → 服务端 | `typing` | `{room_id, is_typing}`，房间内其他连接收到 `user_typing` |
| 客户端 → 服务端 | `ping` | `{ping_id}`，建议在线时每 30 秒发送一次，后端回 `pong` 并更新活跃时间 |
| 服务端 → 客户端 | `error` | `{message}`，例如加入房间失败。握手失败监听 Socket.IO 的 `connect_error` |

发送时用 `temp_id` 关联本地待发送气泡与 `message_ack`。ACK 成功表示后端已保存消息，随后用 `message_id` 将本地气泡与 `new_message` 合并。ACK 失败时展示 `error`。断线或 ACK 超时时，先刷新历史确认是否已经保存；`temp_id` 只用于关联回执，重复发送可能生成新消息。REST 的 `POST /chat-system/chat/rooms/{room_id}/messages` 会落库并返回发送结果，实时聊天应走 `send_message`，避免重复落库并让对方立即收到推送。

会话重连后重新加入当前房间，刷新会话列表和当前房间历史，与已收到的实时消息按 ID 合并。历史分页没有 `sequence` 字段；如后续需要序列号补拉，可用实时保存的每房间序列号调用 `fetch_offline_messages`，详见 [WebSocket 聊天系统使用指南](websocket/WebSocket聊天系统使用指南.md#websocket-事件)。离线跨度超过一页时继续拉历史，直到与此前已有消息重叠或拉完。

## 6. JavaScript 示例

REST 与 Socket.IO 示例共用 `getAccessToken()`，接入应用现有的登录状态。示例采用前端和后端同源代理，直连时把 `origin` 传为后端地址。

```javascript
export function createChatApi(getAccessToken, origin = window.location.origin) {
  async function request(path, { method = 'GET', body } = {}) {
    const headers = { Authorization: `Bearer ${getAccessToken()}` };
    if (body !== undefined) headers['Content-Type'] = 'application/json';

    const response = await fetch(`${origin}/chat-system/chat${path}`, {
      method,
      headers,
      body: body === undefined ? undefined : JSON.stringify(body),
    });
    const result = await response.json().catch(() => ({}));
    if (!response.ok || result.code !== 200) {
      throw Object.assign(new Error(result.message ?? `聊天请求失败（HTTP ${response.status}）`), {
        status: response.status,
      });
    }
    return result.data;
  }

  return {
    openPrivate: (userId, userType = 'NormalUser') => request('/rooms', {
      method: 'POST',
      body: { type: 'private', participants: [{ user_id: userId, user_type: userType }] },
    }),
    listRooms: (page = 1) => request(`/rooms?page=${page}&per_page=20&include_hidden=false`),
    getHistory: (roomId, page = 1) => request(`/rooms/${roomId}/messages?page=${page}&per_page=20`),
    markRead: (roomId) => request(`/rooms/${roomId}/read`, { method: 'POST' }),
  };
}
```

Socket.IO 示例把事件转给页面或聊天 store。`onConnected` 用于刷新列表和当前会话；`onPending` 写入临时气泡，`onAck` 按 `temp_id` 更新它，`onMessage` 按消息 ID 合并。监听在首次连接前注册，登录期间复用一个连接，退出登录时调用 `disconnect()`。

```javascript
import { io } from 'socket.io-client';

export function createChatSocket(getAccessToken, handlers, origin = window.location.origin) {
  const socket = io(origin, {
    path: '/socket.io',
    autoConnect: false,
    auth: (callback) => callback({ token: getAccessToken() }),
  });
  let activeRoomId = null;
  let heartbeat;

  function stopHeartbeat() {
    clearInterval(heartbeat);
  }

  socket.on('connected', () => {
    stopHeartbeat();
    if (activeRoomId !== null) socket.emit('join_room', { room_id: activeRoomId });
    heartbeat = setInterval(() => {
      if (socket.connected) socket.emit('ping', { ping_id: Date.now() });
    }, 30_000);
    handlers.onConnected();
  });
  socket.on('message_ack', handlers.onAck);
  socket.on('new_message', (message) => handlers.onMessage({ ...message, id: message.message_id }));
  socket.on('disconnect', stopHeartbeat);
  socket.on('connect_error', handlers.onConnectError);
  socket.on('error', handlers.onError);

  return {
    connect: () => socket.connect(),
    disconnect: () => {
      stopHeartbeat();
      socket.disconnect();
    },
    selectRoom(roomId) {
      if (roomId === activeRoomId) return;
      if (socket.connected && activeRoomId !== null) {
        socket.emit('leave_room', { room_id: activeRoomId });
      }
      activeRoomId = roomId;
      if (socket.connected && roomId !== null) socket.emit('join_room', { room_id: roomId });
    },
    sendText(roomId, text) {
      const content = text.trim();
      if (!content) throw new Error('消息内容不能为空');
      if (!socket.connected) throw new Error('聊天已断线，请重连后发送');
      const payload = { room_id: roomId, content, type: 'text', temp_id: crypto.randomUUID() };
      handlers.onPending(payload);
      socket.emit('send_message', payload);
    },
  };
}
```

打开私聊时先 `api.openPrivate(userId)`，再用返回的 `room_id` 调用 `chat.selectRoom(roomId)` 和 `api.getHistory(roomId)`。从会话列表进入时直接使用 `room.id`。给每条历史消息补上当前房间的 `room_id`，以 `(room_id, id)` 合并历史和实时消息；渲染时按 `created_at` 和 `id` 升序。聊天页关闭时调用 `chat.selectRoom(null)`。

握手因 token 过期被拒绝时，在 `onConnectError` 中复用应用的刷新流程，拿到新 access token 后调用 `chat.connect()`。网络自动重连时，每次握手也会重新读取 `getAccessToken()`。

## 7. 联调顺序

1. 用两个普通用户账号登录，A 发起 B 的私聊。再次打开同一私聊，确认 `room_id` 一致。
2. B 保持在会话列表，A 发送一条文本。确认 A 收到 `message_ack` 和 `new_message` 后只展示一条，B 的列表能收到实时事件，并可刷新得到未读数。
3. B 打开聊天，确认历史可见、标记已读后会话列表未读数归零。发送足够多的消息后上滑检查分页顺序与去重。
4. B 断线期间由 A 继续发送。B 重连后刷新列表和历史，确认离线期间的消息可见，实时与历史合并后无重复气泡。
