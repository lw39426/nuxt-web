# 技术方案设计文档（反推版）

## 1. 文档说明

- 文档类型：基于现有代码的技术反向方案

- 适用项目：domeWeb

  Nuxt 4+Vue 3 +Python+ Vue Router +TypeScript +UnoCSS+ GSAP + Nuxt UI+ @AI-SDK+ESLint + Prettier

  项目工作：

  **v** ***\*项目职责\****：

  使用gasp绘制动画，flip动画，移动端响应式适配

  采用fetch+sse流式解析结合虚拟滚动css锚定解决长文本渲染抖动

  Ai提示词优化、markdown预览

  接入sentry前端监控系统建立异常监控与报警机制，钉钉机器人消息推送

## 2. 技术目标

1. 支撑“AI 对话 + 内容 + 商品 + 角色展示”的统一 Web 体验
2. 在不破坏当前交互体验的前提下补齐业务闭环能力
3. 形成可演进的前后端契约与部署体系

## 3. 技术栈与基础设施

## 3.1 前端与全栈框架

1. Nuxt 4.2.1（含 Nitro Server）
2. Vue 3.5.x + Vue Router 4
3. TypeScript 严格模式
4. UnoCSS + Nuxt UI

## 3.2 AI 与交互能力

1. @ai-sdk/vue + ai
2. @ai-sdk/openai（兼容接入 SiliconFlow）
3. GSAP（高性能动画）

## 3.3 工程工具链

1. ESLint + Prettier
2. simple-git-hooks + lint-staged
3. PNPM 包管理

## 4. 总体架构

## 4.1 架构形态

采用 Nuxt 全栈同仓架构：

1. app 目录承载页面、组件、状态与前端业务逻辑
2. server/api 目录承载 BFF/Mock 接口
3. composables 统一封装 API 契约与状态访问

## 4.2 分层设计

1. 展示层：pages + components
2. 状态层：useState/useCookie + 业务 composables
3. 数据访问层：useApi 统一请求客户端
4. 服务层：server/api 各业务 handler
5. 外部能力层：SiliconFlow、远端角色数据服务

## 5. 关键模块方案

## 5.1 AI 对话模块

### 5.1.1 前端

1. 使用 Chat 对象驱动消息流
2. 会话本地持久化（localStorage）
3. 支持错误兜底、复制、重试、滚动状态管理
4. 支持首页 query 注入首问并消费后清理 URL

### 5.1.2 后端

1. chat.post.ts 对输入做结构与长度校验
2. streamText 流式输出 UIMessage
3. 环境变量控制 AI 可用性与模型选择
4. 对 401/403/404/API 异常做分类错误映射

### 5.1.3 安全与风控建议

1. 增加请求频控（IP + 用户维度）
2. 增加敏感内容分级与审计日志
3. 增加 AI 响应超时与重试策略

## 7. 前端工程方案

## 7.1 应用壳

1. app.vue 使用 UApp + NuxtLayout + 全局加载器
2. default 布局通过路由 meta 控制 navbar/footer/floating 显隐
3. auth 布局用于登录注册独立视觉

## 7.2 状态管理

1. 全局状态优先 useState
2. 鉴权状态：useAuthState + auth_token Cookie
3. 主题状态：useThemeMode + localStorage 持久化

## 7.3 数据请求规范

1. useApi 统一 baseURL、凭证与 Authorization 注入
2. 响应以 code===200 判定业务成功
3. 统一抛出 ApiError（message/code）

## 7.4 动画与渲染策略

1. 导航栏使用 FLIP 思路减少布局抖动
2. 角色页使用 GSAP 控制复杂转场
3. 长内容区域使用 content-visibility 优化

## 8. 后端与 BFF 方案

## 8.1 目录规范

1. server/api/<domain>/<action>.get.ts
2. 统一返回结构：code/message/data/timestamp

## 8.2 AI 服务层

1. Provider：SiliconFlow（OpenAI 兼容）
2. 系统提示词：心理陪伴语气与风险提醒
3. 错误映射：模型不可用、鉴权失败、权限不足、网络异常

## 8.3 Mock 到真实服务迁移

1. 第一步：保持返回结构不变，仅替换数据源
2. 第二步：按域拆 repository/service
3. 第三步：接入数据库与缓存

## 9. 非功能技术方案

## 9.1 性能

1. 图片懒加载与关键资源预连接
2. 重要动画只在必要属性上做过渡（transform/opacity 优先）
3. 移动端动画分支降级，避免强制回流
4. 通过页面级指标持续观测（LCP/INP/CLS）

## 9.2 稳定性

1. 全局加载看门狗（避免白屏挂死）
2. AI 错误分类兜底
3. 本地缓存容错（JSON 解析失败回退）

## 9.3 安全

1. 服务端密钥仅在环境变量维护
2. 建议新增接口鉴权中间件
3. 建议新增请求日志脱敏与审计

## 9.4 可观测性

1. 建议统一日志结构（traceId/userId/path/status/cost）
2. 建议接入错误告警（Sentry 或等价方案）
3. 建议新增关键埋点：路由耗时、AI 首字延迟、接口失败率

## 10. 部署与运维方案

## 10.1 当前部署路径

1. Nuxt build 输出 .output
2. Node 直接运行或 PM2 守护
3. Nginx 反代到 Nitro 端口
4. 可选 Docker 部署

## 10.2 环境变量建议

1. AI_ENABLED：开启/关闭 AI 服务
2. SILICONFLOW_API_KEY：模型访问密钥
3. AI_MODEL：模型标识
4. NUXT_PUBLIC_API_BASE：前端 API 基础路径
5. NUXT_PUBLIC_USE_MOCK：是否启用 Mock

## 10.3 发布策略建议

1. dev：全量调试与 mock
2. staging：真实接口联调 + 监控验证
3. prod：最小化 sourcemap 与严格日志级别

## 14. 结论

当前工程具备优秀的前端体验基础与清晰的可扩展结构，适合作为“AI+内容+商品”融合产品的中期演进底座。下一步关键在于补齐用户、交易、内容扩展接口闭环，以及建立可观测与稳定性治理体系，使其从演示级能力升级为可持续交付的业务系统。
