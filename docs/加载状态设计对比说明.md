# 加载状态设计对比说明（Nuxt 4）

## 1. 背景
在页面刷新或路由跳转时，用户会经历短暂白屏。此前只依赖约定式加载页，无法稳定覆盖所有场景，尤其是客户端渲染、路由生命周期边界、异常中断时的可视反馈。

本次改造目标是：
- 刷新与跳转时都能看到明确的“加载中”反馈。
- 避免“浏览器已加载完成但页面仍白屏”的无感等待。
- 加入兜底机制，避免加载层异常不消失。

## 2. 旧方案与新方案差异

### 2.1 旧方案（约定式）
- 核心文件：`app/loading.vue`
- 思路：使用 Nuxt 约定文件提供加载占位。
- 特点：接入简单、侵入小。
- 局限：在复杂页面生命周期下，可见性不稳定；对异常中断与长耗时场景控制力弱。

### 2.2 新方案（根级状态驱动）
- 核心文件：
  - `app/components/AppGlobalLoader.vue`
  - `app/plugins/page-loading.client.ts`
  - `app/app.vue`
  - `app/assets/css/main.css`
- 思路：通过根组件常驻全屏加载层，使用插件监听 Nuxt 页面生命周期统一控制显隐。
- 特点：
  - 刷新、路由切换、异步加载过程反馈更稳定。
  - 可集中管理进入/退出时机。
  - 支持异常兜底（watchdog 超时自动收敛）。

## 3. 两种实现介绍

## 3.1 实现 A：约定式加载页（loading.vue）

### 文件
- `app/loading.vue`

### 工作方式
- 由 Nuxt 约定机制在特定加载阶段显示页面级占位。

### 适用场景
- 项目规模较小。
- 页面数据加载逻辑简单。
- 对加载时机精细控制要求不高。

### 优缺点
- 优点：接入快，维护成本低。
- 缺点：难覆盖全部白屏来源，缺少统一的错误/超时控制。

## 3.2 实现 B：根级全屏加载层 + 生命周期钩子（当前方案）

### 文件
- `app/components/AppGlobalLoader.vue`：全屏加载层视图。
- `app/plugins/page-loading.client.ts`：生命周期监听与状态机。
- `app/app.vue`：挂载 `AppGlobalLoader` 和 `NuxtLoadingIndicator`。
- `app/assets/css/main.css`：加载层与过渡动画样式。

### 工作方式
1. 在根组件中常驻加载层组件。
2. 插件监听 `page:start`、`page:finish`、`app:error`，并在 `router.beforeEach` 判断是否为软导航（同页面记录，仅参数变化）。
3. 通过共享状态 `globalPageLoading` 控制全屏遮罩显示/隐藏。
4. 使用 `NuxtLoadingIndicator` 提供顶部进度反馈。
5. 通过 watchdog（12s）避免异常状态下加载层长期停留。
6. 全屏遮罩在非软导航时立即显示，并设置最短可见时长（180ms），减少抖动。

### 适用场景
- 中大型项目。
- 页面依赖接口较多，加载链路复杂。
- 需要稳定、统一、可兜底的加载体验。

### 优缺点
- 优点：可控性高、覆盖范围广、可兜底。
- 缺点：实现复杂度略高，需要维护插件逻辑。

## 4. 无用文件检查结果

本次检查的加载相关文件：
- `app/app.vue`
- `app/components/AppGlobalLoader.vue`
- `app/plugins/page-loading.client.ts`
- `app/loading.vue`
- `app/assets/css/main.css`

检查结论：
1. `app/components/AppGlobalLoader.vue`：正在使用（由 `app/app.vue` 直接挂载）。
2. `app/plugins/page-loading.client.ts`：正在使用（位于 `app/plugins`，Nuxt 自动注册）。
3. `app/assets/css/main.css`：正在使用（由 Nuxt 全局 css 配置引入）。
4. `app/loading.vue`：潜在冗余。
   - 原因：当前已由根级加载层覆盖主要加载场景，且两套机制可能造成重复或冲突感知。
   - 建议：
     - 若后续验证中未再观察到 `loading.vue` 的独立价值，可删除该文件。
     - 若希望保留 Nuxt 约定式回退，可保留，但应简化样式避免与全屏加载层重复表达。

## 5. 推荐落地策略
- 主方案保留“根级状态驱动加载层”。
- 将 `loading.vue` 作为可选回退策略，而非主展示层。
- 后续可按页面颗粒度补充局部 skeleton，减少全屏遮罩出现频率，提升体感流畅度。

### 当前决策补充
- 已取消“延迟 260ms 再显示全屏加载层”的策略。
- 当前策略为：非软导航立即显示全屏加载层；软导航（同页面 params/query/hash 变化）不显示全屏加载层。

## 6. 验证清单
- 刷新任意页面：应先看到全屏加载层，再进入页面内容。
- 路由跳转：应看到顶部进度条，必要时显示全屏加载层。
- 断网或接口慢：加载层不应无限停留（watchdog 兜底）。
- 错误页：出现错误时加载层应及时关闭。
