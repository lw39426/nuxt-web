# 主题系统重构 — 设计规格与实施计划

**日期**: 2026-08-19
**状态**: P1 / P2 / P3 已完成；P4 已实施（推荐按 §11 验证清单做一轮上线前回归）
**核心决策**: `@nuxtjs/color-mode`（.dark class）做开关 + CSS 变量（theme.css）做唯一事实源 + uno.config.ts 做映射层

---

## 1. 背景与目标

当前网站主题切换存在"样式混乱"问题：

- 三套配色机制并存：自定义语义 token（`home-*` / `mingtext-*` / `card-*`）、Tailwind/UnoCSS 原始色阶（`gray-*`）、散落的硬编码任意值（如 `#202327`、`bg1`）。
- 每个 UI 元素几乎都要写双份 `bg-white dark:bg-zinc-900` 形式的类，心智负担重、易漏。
- `main.css` 存在主题无关的硬编码深色（`body { background: #08070f }`）。
- `docs/主题切换文档.md` 描述的旧实现文件（`useThemeMode.ts`、`theme.client.ts`）已删除，文档严重过期。

**目标**：

1. 单一事实源：颜色值统一收归 `theme.css`，加新主题只改一个文件。
2. 消灭 `dark:` 双写：通过 CSS 变量代理，`.dark` 出现时语义类自动翻转。
3. 可扩展：light/dark 为一等公民，其余主题（oled / sepia）作为"明暗色调变体"扩展。
4. 主流程零回归：每个阶段可独立上线。

---

## 2. 现状分析（改动前）

| 位置 | 现状 | 问题 |
|------|------|------|
| `nuxt.config.ts` `colorMode` | `preference:'system'`, `classSuffix:''`, `disableTransition:true` | ✅ 合理，保留 |
| `@nuxt/ui` v4 | `@variant dark (&:where(.dark, .dark *))`（class 策略） | ✅ 与 .dark 一致 |
| `uno.config.ts` `theme.colors` | `home / mingtext / card` 三组业务色板 | 命名语义不清、`breadcrumbDark`/`accentDark` 基本是死代码、`home.white`/`home.light` 同值冗余 |
| `uno.config.ts` `shortcuts` | 内嵌 `dark:` 双写 | 可读性差；`badge-gray` 引用不存在的 `gray-550` |
| `main.css` | `body` 硬编码深色 | light 主题下个别区域会露黑底 |
| 各组件 | `bg-white dark:bg-*` 双写 | 全部要迁移 |

## 3. 决策记录

### 3.1 方案对比

| 维度 | 方案 A（自建 `data-theme`） | 方案 B（@nuxt/ui 集成）✅ |
|------|---------------------------|--------------------------|
| 主题开关 | `data-theme="dark"` 属性 | `.dark` class（@nuxt/ui 原生）+ `data-theme` 做扩展 |
| 防闪烁 | 手写内联脚本 | `@nuxtjs/color-mode` 内置 |
| 切换 API | 自定义 `useTheme()` | `$colorMode.preference` / `useColorMode()` |
| 与 @nuxt/ui 关系 | 平行世界，手动覆盖 `--ui-*` | 同层共生，`.dark` 一加全部自动变色 |
| 类名写法 | 双写或自定义 shortcuts | `bg-surface` 单写，变量自动翻转 |
| 多主题扩展 | light/dark/blue/purple 完全平级 | light/dark 一等公民，其余是明暗色调变体 |
| 变量层级 | 业务驱动 | 设计系统驱动（原始色板 + 语义 token） |

**选定方案 B。**

### 3.2 关键细节决策

- **映射层放 `uno.config.ts` 而非 Tailwind `@theme`**：避免与 Tailwind v4 扫描器对它感知不到的配置字符串类名失效的问题；与现有 `home-*` 机制同路径，shortcut 也能可靠引用。
- **带颜色/状态（hover: 等）的组合类放 theme.css 用普通 CSS 定义**（直接 `var()` 引用语义 token），不用 uno shortcuts、也不用 `@apply`——Tailwind v4 vite 插件会处理 main.css 的 import 链并拦截 `@apply` 中的 UnoCSS 语义类（见 §6.2 的坑）。
- **@nuxt/ui 组件的 `--ui-*` 主题暂不接管**（U 组件自主题），只统一自定义 UI。需要时在 theme.css 覆盖 `--ui-bg` / `--ui-text` 等高频 key。

## 4. 架构设计（4 层）

```
① 引擎层   @nuxtjs/color-mode + nuxt.config.ts    → 控制 <html> 上的 .dark
② 事实源   app/assets/css/theme.css               → CSS 变量：原始色板 + 语义 token（.light/.dark）
③ 映射层   uno.config.ts                          → theme.colors 把 var 映射成类名；纯布局 shortcuts
④ 组件层   组件直接写语义类（bg-surface / text-fg …）
```

| 文件 | 职责 | 什么时候改 |
|------|------|-----------|
| `app/assets/css/theme.css` | 主题唯一事实源：token 定义 + 主题块 + `@apply` 组件类 | 换主题/调色 |
| `uno.config.ts` | ① 语义色板→类名映射 ② 纯布局 shortcuts | 加映射/加布局类 |
| `main.css` | reset、非主题样式；**删除硬编码颜色** | P4 |
| `nuxt.config.ts` `colorMode` | 开关引擎 | 基本不改 |

### 5.1 原始色板（各主题共享）

```css
:root {

  --brand-300: #5ce6c0;
  --brand-200: #8ff2d8;
  --brand-600: #0aa374;
  --brand-700: #087e5c;

```

### 5.2 语义 token（随主题翻转）

| 语义 | CSS 变量 | 生成类（示例） | 说明 |
|------|----------|----------------|------|
| 页面底色 | `--canvas` | `bg-canvas` | 原 `bg-white dark:bg-black` |
| 悬浮/弹层底色 | `--canvas-elevated` | `bg-elevated` | |
| 卡片表面 | `--surface` | `bg-surface` | 原 `card.light/dark` |
| 次级表面 | `--surface-muted` | `bg-surface-muted` | |
| 毛玻璃 | `--glass-bg` | `bg-glass` | 导航栏/悬浮面板（已映射） |
| 主文字 | `--fg` | `text-fg` | |
| 次级文字 | `--fg-muted` | `text-fg-muted` | |
| 弱文字 | `--fg-subtle` | `text-fg-subtle` | |
| 线框 | `--line` / `--line-strong` | `border-line` / `border-line-strong` | |
| 品牌实底 | `--brand` | `bg-brand` / `text-brand` | |
| 品牌弱底 | `--brand-soft` | `bg-brand-soft` | 用于 hover/选中底 |
| 品牌 hover | `--brand-hover` | `hover:bg-brand-hover` | light 加深、dark 变亮 |
| 品牌 active | `--brand-active` | `active:bg-brand-active` | |
| 品牌上文字 | `--on-brand` | `text-on-brand` | |
| 强调 | `--accent` / `--accent-soft` | `bg-accent` / `bg-accent-soft` | 占位，未全站统一 |
| 阴影/遮罩 | `--shadow-soft` / `--overlay` | 直接 var 引用 | |

    fgMuted: 'var(--fg-muted)',
    fgSubtle: 'var(--fg-subtle)',
    line: 'var(--line)',
    lineStrong: 'var(--line-strong)',
    brand: 'var(--brand)',
    brandSoft: 'var(--brand-soft)',
    brandHover: 'var(--brand-hover)',
    brandActive: 'var(--brand-active)',
    onBrand: 'var(--on-brand)',

### 5.4 新代码规范（对开发者的约定）

```html
<!-- 推荐 -->
<div class="bg-canvas text-fg border-line">…</div>
<button class="bg-brand text-on-brand hover:bg-brand-hover active:bg-brand-active">主按钮</button>

<!-- 禁止 -->

<button class="bg-brand/90 …">…</button>   <!-- /opacity：静默丢弃，见 §6.1 -->
```

## 6. 关键技术坑（实测结论，勿踩）

### 6.1 `/opacity` 修饰符对 var() 色"静默丢弃"

实测（unocss 66.5.10-beta.1）`hover:bg-brand/90` 生成的 CSS 是：

```css
.hover\:bg-brand\/90:hover { background-color: var(--brand); }  /* /90 被静默丢弃！ */
```

**不是报错、不是警告，而是一个"看起来生效但实际无效果"的错误样式。** 规避：透明度/交互态一律用 `-soft` / `-hover` / `-active` 变体，禁止 `*/数值` 写法。

### 6.2 uno shortcuts 对"多段颜色名 + 变体"静默丢弃

实测 shortcut 内：
- `text-fg`（单段）✅ 可解析
- `bg-brand` ✅、`hover:bg-brand-hover`（变体）❌、`text-fg-muted`（多段）❌ 被静默丢弃

**规避：带颜色/状态（hover: 等）的组合类不再用 @apply 引用语义类**（实测 Tailwind v4 vite 插件会处理 `main.css` 的整条 import 链，`@apply text-fg` 等语义类会报 `Cannot apply unknown utility class` 直接构建失败）。theme.css 第 4 节已改用**普通 CSS + var() 引用语义 token**（如 `.read-more-btn:hover { background-color: var(--brand-hover) }`），可靠且无双引擎冲突。

### 6.3 其他

- `tailwindcss`（@nuxt/ui）与 UnoCSS 双引擎并存，本方案 token 类由 UnoCSS 生成，避免依赖 Tailwind 对配置字符串类的扫描。
- `.section-header-label` 的颜色由使用处各自指定（各区块品牌色不同），shortcut 内不内嵌颜色。

## 10. 扩展新主题指南

加"非明暗"主题（oled / sepia）：

```css
[data-theme='oled'] {
  --canvas: #000;
  --surface: #050505;
  --fg: #eee;
  /* …覆盖需要的语义 token 即可 */
}
```

- 切换开关仍需扩展 `useColorMode` 或自定义逻辑（P3 尾期再评估）。
- 不建议用 `data-theme` 替代 `.dark` 管理明暗（会破坏 @nuxt/ui 自动适配）。

## 12. 风险与后续

- **版本风险**：unocss 66.5.10-beta 的 shortcut 缺陷 → 已用 `@apply` 规避，后续升稳定版后可在验证通过的前提下回迁。
- **`/opacity` 全面禁用**：需在团队约定 + 后续 eslint 规则中固化。
- **@nuxt/ui 主题**：暂不接管，若品牌化需求明确，可在 theme.css 覆盖 `--ui-*` 高频 key。
