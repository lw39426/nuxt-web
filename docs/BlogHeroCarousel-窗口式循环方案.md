# BlogHeroCarousel 叠卡循环实现

本文记录博客页和首页共用的叠卡轮播。早期窗口式实现通过三个槽位移动轨道，动画结束后再更新内容并复位。当前实现直接更新逻辑索引，每张卡片按相对位置过渡，切换结果在索引更新时就已确定。这样，关闭 CSS 过渡或连续切换时，循环也能正常工作。

## 组件职责

| 文件 | 职责 |
| --- | --- |
| [BlogHeroCarousel.vue](../app/components/BlogHeroCarousel.vue) | 接收 Banner 列表，计算叠卡位置，渲染图片、链接、控制按钮和请求状态。 |
| [useStackedCarousel.ts](../app/composables/useStackedCarousel.ts) | 管理索引、循环切换、指针手势、自动播放和清理。 |
| [博客页](../app/pages/blog/index.vue) | 提供轮播数据、请求状态及重试回调，使用 `hero` 排版。 |
| [首页资讯](../app/components/home/LatestNews.vue) | 复用轮播组件，使用 `compact` 排版与 `h3` 标题。 |

## 卡片怎么排列

组件根据每张卡片和当前索引的循环距离计算偏移。距离为零的卡片居中；正负偏移决定在右侧或左侧；距离越大，卡片越小、越淡，层级越低。距离大于二的卡片隐藏。CSS 用 `--offset`、`--scale` 和拖动偏移组合出位移与缩放。

组件按数据逐项渲染，真实卡片使用 Banner ID 作为键。切换时同一张卡片保留自己的 DOM，CSS 对位置和透明度做过渡。有两条数据时额外生成一张镜像侧卡，供桌面布局显示另一侧预览，镜像卡从键盘焦点和无障碍树中排除。小屏隐藏最外侧卡片。

## 切换与播放

左右箭头、方向键、分页点、侧卡和拖动最终都调用 `goTo()`。它将目标索引归一化到有效范围，因此在首张向前或末张向后都能循环。点侧卡会先将它选为当前项；有链接的中央卡片才可打开目标页面。

拖动由 Pointer Events 处理。水平拖动时卡片跟随指针偏移，偏移为水平距离的 30%，最大 60px。松手时，水平移动超过 40px 且大于垂直移动才换卡。小幅拖动回到原位，拖动后抑制可能误触的链接点击。

自动播放每 5 秒切换一次，主动切换后重新计时。悬停、焦点在轮播内、拖动或页面隐藏都会暂停播放。暂停原因由集合管理，只有所有原因消失才恢复。开启「减少动效」时，自动播放和 CSS 过渡停用，手动切换仍可使用。数据条数变化时重置索引和拖动状态，组件卸载时清除定时器及全局监听。

## 数据状态与排版

| 场景 | 表现 |
| --- | --- |
| 正在加载 | 显示共用占位图和「正在加载轮播…」。 |
| 请求成功但没有数据 | 显示占位图和「暂无轮播内容」。 |
| 请求失败 | 显示失败提示和重试按钮，发出 `retry` 事件，由调用方重新请求。 |
| 单张封面缺失或加载失败 | 由 `UiImage` 显示占位图，该条内容和链接仍可使用。 |
| 只有一张卡片 | 显示中央卡片，停用切换控件和自动播放。 |

父组件控制容器比例和版面位置。博客页从小屏的 8:5 调整到桌面的 16:6，并在中等及以上视口限制最大高度为 60vh。组件内部通过 `hero` 和 `compact` 控制排版，卡片圆角由轮播组件负责。

## 验证方式

[轮播单测](../tests/unit/composables/useStackedCarousel.test.ts) 覆盖双向回环、重叠暂停原因、数据缩减及卸载后的定时器清理。

```sh
pnpm exec vitest run tests/unit/composables/useStackedCarousel.test.ts
```

浏览器中可用零张、一张、两张和多张数据核对空状态、两侧预览及回环，再分别检查鼠标、触屏、方向键和减少动效模式。请求失败与封面加载失败可分开验证，前者应提供重试，后者应保留该条内容。
