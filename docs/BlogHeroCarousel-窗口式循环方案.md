# BlogHeroCarousel 窗口式循环方案（方案 A）

> 实施日期：2026-10-27
> 组件：`app/components/BlogHeroCarousel.vue`
> 使用方：`app/pages/blog/index.vue`（hero 排版）、`app/components/home/LatestNews.vue`（compact 排版）

## 1. 背景：旧实现为什么会被卡住

旧实现用「克隆轨道」做无缝循环：

```
索引：   0        1    2    3    4    5        6
DOM：  [末页克隆] [一] [二] [三] [四] [五] [首页克隆]
指针： current ∈ 0..n+1，有效内容在 1..n
```

滑到克隆页后，等 `transitionend` 再瞬跳回真实页。问题不在某一次动画，而在这个结构本身：

- **循环正确性依赖异步事件与可变指针在接缝处对齐**。事件晚到、早到、不派发，都会让 `current` 停在 0 或 n+1。
- **首尾克隆页可能与相邻真实页画面完全一致**。从第 1 张滑向末页克隆时，计算后的位移可能没有变化，浏览器不产生过渡，也就不会派发 `transitionend`。
- **存在可停靠的中间态**。一旦停在 0，`prev()` 的边界判断会直接 return，用户表现为「怎么滑都不动」。之前补的 700ms 定时器只是兜底，每加一条兜底就多一条竞态路径。

结论：要根治，就得让这种中间态**不存在**，而不是继续补事件。

## 2. 方案 A 的核心不变量

DOM 永远只有三格：

```
槽位：   0（上一张）   1（当前）   2（下一张）
静止：  translateX(-100%)，槽位 1 居中
索引：  index ∈ 0..n-1，循环靠取模
```

- 上一张 = `posts[(index - 1 + n) % n]`
- 当前 = `posts[index]`
- 下一张 = `posts[(index + 1) % n]`

三条不变量：

1. **索引域恒为 `0..n-1`**，不存在 0 / n+1 这类特殊状态。
2. **每次切换恰好位移一格**（next 到 -200%，prev 到 0%），过渡必然发生，`transitionend` 必然派发。
3. **落点轮转内容后瞬跳回 -100%**。落点前后视口里是同一篇文章的同一位置，像素级不可见。

## 3. 状态机与时序

状态只有两个：

| 状态 | 取值 | 含义 |
| --- | --- | --- |
| `index` | `0..n-1` | 当前逻辑索引 |
| `phase` | `idle` / `next` / `prev` | 轨道槽位：1 / 2 / 0 |

### next

```
idle(-100%) --phase=next--> 动画到 -200%
                           --transitionend--> index=(index+1)%n
                                              phase=idle
                                              transition:none 瞬跳回 -100%
                                              forced reflow 后恢复过渡
```

### prev

与 next 对称：动画到 0%，收尾 `index=(index-1+n)%n` 后瞬跳回 -100%。

### 指示点

静止位始终是 -100%，所以指示点不需要动画：`phase === idle` 时直接改 `index`，内容原地轮转。

### 拖拽

- 跟手阶段：`translateX(calc(-100% + dx))`，`transition:none`
- 松手：`|dx| > 50px` 且水平主导 → 进入 next / prev 动画；否则过渡回 -100%
- 动画期间开始的手势直接忽略，不会和正在进行的切换抢状态

### 输入互斥

`phase !== 'idle'` 时，箭头、指示点、拖拽全部忽略。快速连点三次只前进一张，不会叠加、不会跳张。

## 4. 新旧实现对比

| 维度 | 旧实现（克隆轨道） | 方案 A（窗口轨道） |
| --- | --- | --- |
| DOM 数量 | `n + 2`（博客页 7 张，首页 5 张） | 恒为 3 张 |
| 索引域 | `0..n+1` | `0..n-1` |
| 循环机制 | 克隆首尾 + 事件瞬跳 | 取模轮转 |
| 接缝位移 | 首/末克隆可能零位移，过渡与事件可能不发生 | 每次恰好一格，过渡必然发生 |
| 收尾依赖 | `transitionend` + 700ms 定时器兜底 | 仅 `transitionend` |
| 可卡死的中间态 | 0 / n+1 | 不存在 |
| 键盘可达性 | 克隆页里的重复链接也能 Tab 到 | 只有当前张可聚焦，两侧 `aria-hidden` + `tabindex=-1` |
| 重复内容 | 克隆页重复 `h1` 与链接 | 无重复 |
| 关键代码 | `current` / `clonedTrack` / `jumpTo` / `finishSlide` / `scheduleFinish` | `index` / `phase` / `visibleSlides` / `settle` / `startSlide` |

### 与其他候选方案的关系

- **B. 保留克隆 + 定时兜底**：改动最小，但 7 张重复 DOM 与 0/n+1 中间态仍在，只是把卡死概率压低。
- **C. 取消循环**：代码最少，但右滑到首张就停，属于行为变更。
- **D. 接入 Embla**：能力成熟，但新增依赖、放弃现有自研手感与样式控制方式。

选择 A 的原因：在不改变交互与视觉的前提下根治结构问题，且组件仍保持零依赖。

## 5. 边界处理

| 场景 | 行为 |
| --- | --- |
| `n = 0` | 渲染渐变占位，无轨道、无箭头/指示点 |
| `n = 1` | 只渲染当前一张，静止位 0；不启用箭头、指示点、自动播放 |
| `n = 2` | 两侧槽位是同一篇，取模后切换与回环均正确 |
| 数据长度变化 | 重置 `index=0`、`phase=idle`、拖拽偏移归零；`n>1` 才启动自动播放 |
| SSR | 初始 `index=0`，轨道静止 -100%，首屏直接显示第一篇，无闪烁 |
| 自动播放 | 5s 一次，走同一个 `startSlide('next')`；悬停暂停；动画期间不叠加 |
| 快速输入 | 动画期间箭头/指示点/拖拽全部忽略，一次只走一张 |

## 6. 样式控制约定（本次一并保留）

组件只负责行为与内部排版档位，盒子样式由父级 `class` 决定：

- 组件根节点：`relative w-full overflow-hidden isolate transform-gpu group` + 拖拽光标
- 内部排版：`size="hero"`（博客页大字号）/ `size="compact"`（首页半栏小字号），移动端两档一致
- 圆角边框叠加层用 `rounded-[inherit]`，跟随父级圆角

父级用法：

```html
<!-- 博客页：全宽，桌面封顶 60vh -->
<BlogHeroCarousel :posts="heroPosts" class="aspect-[4/3] md:aspect-[16/11] md:max-h-[60vh] rounded-3xl mb-12" />

<!-- 首页：半栏，与右侧索引列表等高 -->
<BlogHeroCarousel :posts="carouselPosts" size="compact" class="aspect-[4/3] md:aspect-[16/11] rounded-3xl" />
```

### 交互验证（/blog n=5，首页 n=3）

- 连续 next / prev 各 10 次，两个方向都能跨越首尾回环，每次落点都回到 -100%，无残留动画对象。
- 回环序列（/blog）：`… ac95 → eef6`（末→首）、`cd5f → b3ef`（首→末），与普通切换路径完全相同。
- 三次快速连点只前进一张；指示点在动画期间点击被忽略。
- 拖拽 120px 松手：跟手位移 `-100% ± 120px`，松手后创建单张过渡，落点索引 ±1。
- 拖拽 20px 松手：回弹过渡存在，索引不变。
- 长按/拖拽期间自动播放暂停，松手恢复。
- 无障碍：只有当前张链接可聚焦，两侧为 `aria-hidden="true"` + `tabindex="-1"`；控制台无新增错误。

说明：自动化环境的渲染帧被冻结，动画时钟不推进，因此交互验证采用「推进动画时间轴 + 注入 `transitionend`」的方式验证状态机；真实 700ms 动画的连贯性需要在浏览器里目测确认。
