
# 聊天页面运行配置

入口为 /chat，使用现有用户登录状态。页面提供普通用户 ID 发起私聊、会话分页、历史分页和实时文本消息。

REST 经 Nuxt 的 /api/v1/chat/rooms 转发至 NUXT_API_SECRET_BASE 所属主机的 /chat-system/chat/rooms，保留 Authorization，复用 useApi 的 401 刷新流程。

Socket.IO 默认访问网站同源 `/socket.io`。本地运行 `pnpm dev` 时，Nuxt 会把 polling 和 WebSocket 转发到 `NUXT_API_SECRET_BASE` 所属主机，默认是 `127.0.0.1:5050`。修改配置后重启 Nuxt，并启动相应的 Flask 服务。

生产 Nginx 需要将该路径转发到 Flask，启用 WebSocket Upgrade，并支持 polling HTTP 请求。也可以设置 `NUXT_PUBLIC_CHAT_SOCKET_ORIGIN` 为后端公开地址，此时后端需允许前端 Origin。HTTPS 页面需要 HTTPS Socket 地址。

已读仅在页面可见、消息区域滚动到底部时触发。发送超时保留待确认状态并补拉历史，避免自动重复发送。当前连接随聊天页面挂载，离开页面会断开。首版没有全站未读通知、输入状态和管理员类型选择。

需要后端运行并使用两个真实账号验收收发、重连、401、分页和已读。构建与静态检查无法替代后端联调。

聊天页通过页面 meta 的 `navbarScrollBehavior: 'static'` 关闭导航栏随滚动变为胶囊；省略该项时继续跟随滚动，`forceCapsule: true` 可固定为胶囊形态。`fullViewport: true` 启用导航栏占位与聊天工作区共享的整屏布局，消息、会话列表和资料栏各自在内部滚动。聊天页同时隐藏底部对比浮层，避免覆盖输入区。
